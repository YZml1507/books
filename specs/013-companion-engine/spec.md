# specs/013 — 陪伴引擎：从「解盘工具」到「懂她的向导」

> 立项：R3126（2026-09-27）。用户指令：全面全网深度调研→写方案→
> 写规划→循环优化。本 spec 在四批调研（测测/Moonly/Co-Star/CHANI/
> 塔罗师专业流程/命理师断应期/咨询技术/陪伴AI架构/玄学内容创作/
> AI算命痛点报告）基础上成文，与 specs/012 互补：012 修「单条解读
> 的方向感」，013 修「关系层面的连续性」——用户要的是「懂我的向导」
> 不是「每次重新认识的算命机」。

## 调研新增量（012 之外的结构性发现）

1. **测测的档案对象切换**：chat 顶部可切换档案（自己→伴侣→朋友），
   基于对方盘解读关系——「DeepSeek 不认识你的另一半，测测认识」。
   我们有 `me:partner` 档案和合婚数据，但 chat 目前只认「我」。
2. **Moonly 留存飞轮**（30日留存 ~24%）：持续更新的用户档案（情绪
   状态/历史对话/反复出现的问题）+ 反馈观测（是否追问同一问题）。
   「优质的回答→信任→更多上下文→更贴切的回答」数据飞轮。
3. **塔罗师的问题梳理位**：专业流程里解读前先整理问题脉络（时间线+
   当事人意愿），牌阵选错=回答跑题的根源。我们的流程拿到问题直接
   输出——「没猜到用户想要什么」的流程级根因之一。
4. **命理师断应期三层**：大运定吉凶框架→流年定应期→流月定落点。
   我们已有大运+流年锚，流月（本月干支→十神）可算未上。
5. **复购结构**（尚普调研）：复购用户买的是「年度运势追踪」和
   「特定领域决策建议」；首购流失的多是「一次性本命解析」。
   高复购用户要「可能性视角+积极暗示」而非铁板预言——判词直说
   与交权并存正是这个结构，方向已验证。
6. **咨询技术**：释义/内容反应（先把她的问题用自己的话复述一遍
   「你说的是…对吧」）是「被听懂」感的最低成本来源；情感反应
   点出情绪本身。这是「猜到用户想要什么」的技术答案。
7. **情绪惯性**（陪伴AI设计）：单轮情绪是偏移量，长期关系状态是
   底色——上轮还难过、这轮不能秒变欢快。我们 chat 有会话记忆
   但没有情绪惯性层。
8. **陪伴红线**：「辅助性而非替代性」——放大独处能力而非替代
   社交。与我们的交权设计一致，保持。
9. **小红书玄学流量结构**：日期+好运tips（打卡心智）、玄学+生活
   场景（穿搭配色/食谱）、祈福互动（社交货币）——daily 日签已经
   是正确形态。
10. **AI算命三大痛点投诉**（腾讯新闻）：排错盘（DeepSeek 四柱都
    排错——我们确定性排盘是硬优势）、结果不一致（已修）、
    一本正经胡说八道（事实闸已有）。

## 方案（按收益排序）

### P1 问题梳理位（释义先行）——「猜到想要什么」的技术解
chat 系统提示词补一条硬规则：小满回答**先用一句话把她的问题
复述成「其实你是在问…」的确认句式**，再作答。释义本身就是
咨询技术里的内容反应——用户被听懂的感觉从这一行开始。
同时给 facts 里补「她这句话的类型判断」坐标（求解式/倾诉式/
验证式），让回复结构跟着问题类型走：
- 求解式（怎么办/该不该）→ 直接给处方
- 倾诉式（我好烦/分手了）→ 先接情绪再给坐标
- 验证式（是不是/会不会）→ 先给判词再给理由
落地：`_chat_intent` 规则分类器（纯规则零LLM）+ system 规范
+ selftest 钉三类句式结构。

### P2 档案对象切换——「帮TA看」
chat facts 增加 `me:partner` 档案注入（昵称/生日→日主/星座
服务端展开）。用户消息里识别「他/TA/对象/男朋友」提及且
partner 档案在场时，引导语气说「按TA的盘看…」。
落地：services.chat_profile_facts 扩 partner 生日展开 +
_FE _chatFacts 注 partner 行 + system 规范补「给了TA的档案
就用在关系问题上」。

### P3 流月锚——「什么时候」的第三层
_reply_temporal 与 chat facts 补本月干支→日主十神锚：
「这个月是X月——X对你是Y（基调词）」。月令节气边界复用
term_time 节表（当前月干支按节气换月口径，与排盘一致）。
落地：bazi_calc 或 voice 加 `_month_ganzhi(dt)` 纯函数 +
temporal 回复补一行 + selftest 钉月份正确性（节气前后各一例）。

### P4 情绪惯性层——上轮难过这轮不秒嗨
chat 会话档记「她最近一条消息的情绪极性」（规则层三档：
低落/高唤起/中性），下一轮 system 补一行「她刚才情绪偏X，
语气跟上别跳频」。纯规则分类复用 crisis/sensitive 管道。
落地：`_emo_polarity(msg)` 分类器 + sess["last_emo"] +
system 注入行 + selftest 钉（难过→语气规范行出现）。

### P5 复问识别——「你上次问过类似的」
chat facts 已有 resume 槽；扩到**会话内**：同一 session 里
第二次出现同类主题时，facts 补一行「她这轮还在问X方向」
（theme 计数）。Moonly 飞轮的最低成本版本：不建画像库，
先让模型知道她在反复问什么。
落地：sess["topic_count"] 计数 + facts 注入 + selftest 钉。

### P6 解读卡「问题梳理」镜像
塔罗/六爻结果页首行目前已有「针对你的问题「X」」——升级为
梳理位：「你问「X」——这事的主线是<主题>，牌面按这条线看」
（主题=分类器落域词）。让用户确认「它在回答我真正问的」。
落地：tarot/liuyao warm 首行后插梳理行。

### P7（远期，不本轮做）情绪轨迹画像
Moonly 式长期档案（情绪/高频问题/完成度）需要持久存储与
隐私设计——本轮只做 P5 会话内版本，跨天画像等 specs/014。
