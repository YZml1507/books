# specs/011：小满人格连续性——「她认识我」

> R3115 调研立项。specs/010 解决的是「判词敢说、说得具体」；
> 本 spec 解决调研发现的下一个断层：**小满对用户是健忘的**。

## 调研依据（R3115 全网调研摘要）

1. **陪伴 AI 两大死因 = persona collapse + memory rot**
   （arxiv 2607.28818 Anchor 审计：无模型能可靠保持轨迹记忆；
   sloane.world/jenova.ai：修法 = canonical persona + 事实级记忆 +
   关联式上下文注入——记忆该在模型看到消息**之前**注入，
   不是等它自己想起去查）。
2. **情绪支持的度量衡**（HEART 基准, arxiv 2601.19922）：
   - Attunement：点名上下文里的具体细节，而不是泛泛安慰
   - Resonance：推进对话——一个相关追问或一个可执行的下一步
   这正是用户「小满回复很泛泛」投诉的学术化表述。
3. **算命产品的留存结构**（Rork/测测/Saju 报告）：
   - 用户 75-85% 为 18-35 女性，晚间 7 点后、周日晚是高峰
   - 用户要的是「把忧虑整理成文字被接住」，不是预测本身
   - 日更内容必须 per-user-per-day 确定（已具备）
4. **巴纳姆研究的关键反直觉**（Glick 1989）：信者对**负面**
   星象描述的接受度与正面相同——「相克就直说」不损体感，
   反而模糊恭维才掉价（与 specs/010 判词层互证）。

## 现状缺口

- `_chatFacts` 只透传昵称；用户档案（性别/生日）从不进上下文——
  小满可以叫出名字却不知道「她」是谁。
- 聊天事实只认「当前视图」；换视图/改天再来，上次测算像没发生过。
- 服务端收到 `生日：` 类事实不展开——手里能算日主却不算。

## Phase 1（本轮落地）

- P1-1 `services.chat_profile_facts`：客户端 `生日：YYYY-MM-DD`
  事实 → 服务端确定性展开 `日主/五行/太阳星座`（day_ganzhi +
  sun_sign_profile，纯函数零 LLM）。
- P1-2 `_chatFacts`：me 档案注入 `性别` + `生日`（昵称已有）。
- P1-3 `_activeViewFacts` 全局回落：当前视图无盘时扫描
  `lastResult:*`，带「她上次测过X」语境行——跨视图连续感。
- P1-4 `_CHAT_SYSTEM`：档案事实使用规范（用起来，别反问）。

## 后续阶段（排期）

- Phase 2：HEART 式 Attunement 离线评估器——规则层给回复打
  「具体度」分（坐标词命中数/空转词命中数），进 probes 常态闸。
- Phase 3：周日晚/情绪高峰帧 + 「上次聊到X」续聊钩子
  （chat session 内已有历史，缺的是跨天开场白）。

## 边界

- 危机/医疗/财务边界不动；档案事实仅称呼级，不做命运断言。
- 生日属敏感事实：只在用户已主动建档时注入，不猜测不追问。
