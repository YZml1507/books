## 0. 一句话结论

008 解决的是「表达层不像给年轻女性的」，009 解决的是「功能集合根本不是
给年轻女性的」。本 spec 做两件事：

A. **功能大审判**：以目标用户为唯一标尺，把现有功能切成
   保留 / 收进「高级」抽屉 / 删除 三栏，研究型功能全部退出默认视线；
B. **AI 陪伴层**：在确定性排盘结果之上，用 LLM 给用户「闺蜜式」的
   情绪回应（复用既有 llm_polish 异步管道与 agnes 配置，additive 接入）。

## 1. 用户画像（钉死，后续一切裁决引用本节）

**小满，22 岁，应届入职**。通勤刷小红书，对星座塔罗有兴趣但不是圈内人；
打开命理产品的场景是「今天好丧/要面试/他没回消息，想找点确定感」。
她要：秒懂的一句话、好看能转发的图、被安慰而不是被分析。
她跑：术语、表单、书名、需要「学习成本」的任何东西。
她怕：被说教、被暗示「你命不好」、被要求做现实决策。

**裁决标尺（三问，任何功能过堂用）**：
Q1 小满会主动找它吗？（不会 → 不配占首页）
Q2 3 秒内能看懂结果吗？（不能 → 改写或收起）
Q3 它让小满感觉更好还是更焦虑？（更焦虑 → 重写或删）

## 2. 功能大审判（三栏裁决表）

| 功能 | 裁决 | 理由（引用标尺） |
|---|---|---|
| 今日运势卡（daily） | **保留·强化** | Q1/Q3 双过，首页锚点，「每日开盒」是回访理由 |
| 塔罗 | **保留·主力** | Q1 最强（目标用户最熟的品类），仪式感+分享图 |
| 桃花运 | **保留** | Q1 强；结果文案按 P1 复查 |
| 八字合婚 | **保留** | 情侣场景刚需；表单简化（两人生日一次输入） |
| 八字排盘 | **保留·简化** | 输入减到生日三字段+可选时辰；默认 warm 模式 |
| 黄历宜忌 | **保留** | 「今天适合做什么」轻决策，pill 化已达标 |
| 五行起名 | **收进高级** | 场景窄（起名是准妈妈需求，非小满日常） |
| 六爻占卜 | **收进高级** | 摇卦仪式感对新人有门槛；塔罗已覆盖「问事」 |
| 读书·检索 | **收进高级** | Q1 不过：小满不会主动查古籍 |
| 读书·深度研究/定位/比对/书目/研究线程/两书对照/概念研究 | **收进高级** | 全部研究型；Q1/Q2 双不过；书 ID 等内部概念零暴露 |
| AI 陪伴聊（新） | **新增** | 见 US1 |

「高级抽屉」实现形态：首页底部一个不显眼的「🔍 老玩家入口」，
点开是平铺功能列表（不做二次视觉设计——这是给少数人的，不是给小满的）。
**所有被收功能零删除**：路由、API、闸门、探针全部原样保留，
只动「从哪里能到达它」。这是宪法双轨隔离的 UI 版：内容芯不删，入口重排。

## 3. User Stories

### US1 AI 陪伴层「问问小满」（P0，新能力）
**作为**小满，**我想要**排完盘有人用闺蜜的口气跟我说说这件事，**以便**感觉被接住而不是被分析。
- 复用：llm_polish 异步管道（spawn+轮询骨架）、agnes 配置、facts_* 事实
  提取器——排盘坐标事实喂给 LLM 当 grounding，答案不许凭空造命。
- 判据 a：POST /api/chat additive 接入；DISABLE=1 时端点返回明确降级
  （前端隐藏入口，不报错）——LLM 永远不是承重墙（D-244a 沿用）；
- 判据 b：禁语扩容：禁「你要…/你应该…/建议你…」类指令式、禁医疗/心理
  危机话题正面接（识别即转固定安全话术）、禁现实决策建议
  （辞职/分手/投资类问题一律回到「盘是盘，决定是你的」框架）；
- 判据 c：对话**不写库**（零隐私留存，与 history.db 隔离）；每次会话上限
  轮数（防依赖），超限温和收尾；
- 判据 d：E2E——排盘后发起一次对话，回复含排盘事实关键词且零禁语命中。

### US2 首页信息架构二剪（P0）
**作为**小满，**我想要**打开就只有我在乎的几个入口，**以便**不用自己过滤噪音。
- 判据 a：首页默认视线（一屏 + 相关功能区）内「研究型」元素 = 0
  （自动审计：检索/比对/书目/线程/书 ID 等关键词在 home-main 与
  view-bazi 可见区的 DOM 出现数为 0）；
- 判据 b：保留功能入口 ≤5；高级抽屉可达但默认折叠；
- 判据 c：ui_smoke 全量用例映射更新后全绿（被收功能改走抽屉路径，
  用例不减只改导航——不得删用例变绿）。

### US3 排盘表单减负（P1）
**作为**小满，**我想要**只填生日就出结果，**以便**不用理解「真太阳时」「历法」。
- 判据 a：默认字段=年/月/日/性别，时辰折叠为「不知道也行」可选项；
- 判据 b：契约不变（后端 schema 零改动，前端默认值填充）；
- 判据 c：ui_smoke 排盘用例适配后全绿。

### US4 结果页「接住感」改造（P1）
**作为**小满，**我想要**结果页先共情再给信息，**以便**不觉得被机器审判。
- 方向：warm 模式结果头部增加一句情境共情（确定性模板族，非 LLM——
  保证离线可用）；AI 陪伴入口（US1）挂在结果尾部而非头部。
- 判据：禁语清单全量零命中；「仅供娱乐」语义保留措辞软化。

## 4. 非目标

- 内容芯不动：排盘算法、引文契约、eval 体系原样（宪法第三条）。
- 不删任何后端功能与 API——只动入口与默认视线（双轨隔离的 UI 版）。
- 不引入外部资源（第二条红线 3）；AI 聊天不落库（隐私）。
- 008 已完成的视觉/文案成果不回退。

## 5. 排期建议

US2（信息架构二剪，动探针，重，独立一轮）→ US3（轻）→ US4（轻）→
US1（AI 陪伴层，依赖子 agent 勘查报告，独立一轮）。
每轮照旧：判据先行 → 闸门全绿 → 台账 → push。
