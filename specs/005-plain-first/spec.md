# Feature Specification: 知命 — 大白话优先（把古籍从主角降为证据）

**Feature Branch**: `005-plain-first`
**Created**: 2026-08-20
**Status**: Draft
**Phase**: OPTIMIZE
**Author**: 审查轨（本文件由审查轨独占写；同目录 `plan.md` / `tasks.md` 由优化轨写，
宪法第六条文件级分工）
**Input**: 用户直接指示——「全文都只有引经据典，但如果要吸引年轻人就不应该这么做，
年轻人不会愿意去看什么古籍原文，他们只想知道他们的结果如何，能够用大白话讲最好」。
**与 003 / 004 的关系**: 003 管视觉壳（对比度/点击区/动效），004 管内容芯（口吻/结构），
**005 管版面顺序与信息层级**——同样的内容，谁在第 1 屏、谁在折叠层。

## 0. 一句话结论

**004 的文案是对的，问题是它被埋在第 115 屏。**

004 判据 1/2/3 全部通过（一句话 11 字、首屏术语 2 个、禁用词零命中、六爻已会回应
提问），但那些判据测的是**响应对象**，没有测**屏幕**。实测：那句 11 字的人话渲染在
`y=92,794px`，用户要滚 **91,982px** 才能看到它。

**再温柔的文案，埋在第 115 屏也等于不存在。**


固定用例：1998-07-20 14 时 女命，提问「感情运怎么样？」，375×812 视口，warm 模式。

### 1.1 本轮实测发现的一处真实缺陷（已单独立项）

**API 返回 12 段引文，页面渲染 24 段——同一批古籍被渲染了两次。**

- `app.js:610` 渲染 `j.evidence`（12 段，**21,153 字全文**）
- `app.js:302-307` 又渲染 `warm.citations`（同样 12 段，**2,640 字截断版**）
- 逐条比对：**12/12 条目完全相同**，`citations` 独有 0、`evidence` 独有 0

即后端已经做对了截断（`warm.citations` 只有 2,640 字），前端却把全文版和截断版
**同时**渲染出来。这一条占了当前版面的绝大部分。
已记入 `docs/AUDIT_FINDINGS.md` R128a-01（MAJOR）。

## 2. 为什么这不是「文案问题」而是「版面问题」

004 已经交付的东西是好的，不要推翻重做：

- 一句话结论存在且合格（11 字，阈值 ≤20）
- 首屏区块术语 2 个（阈值 ≤3）
- 禁用词 16 词零命中（无吉凶断言、无现实指令）
- 六爻从「不代为断事」改成了「你问的是「感情运怎么样？」。起到的是離卦——附着与依托」
- 幸运数字有真实出处（河图数，《星學大成》等语料实测可挂引文）

**这些都不用改。** 005 只改一件事：**谁排在前面、谁默认折叠。**

根因在 `app.js`：

```
:608  if (j.evidence && j.evidence.length) {
:610      html += renderHits(j.evidence, ...)      ← 21,153 字古籍全文，零截断
:611  }
:613  html += renderVoice(j, '📖 解读（确定性规则）')   ← 大白话在这之后
```

古籍排在大白话**之前**，且 `renderHits` 对原文不做任何长度限制。

## User Scenarios & Testing *(mandatory)*

### User Story 1 — 打开就看见结论（Priority: P0）

**作为**一个刚点完「排盘」的用户，**我想要**不滚动就看到与我有关的那句话，
**以便**不必翻过几万字古籍才找到答案。

**Why this priority**: 这是用户这次指示的核心，也是全项目当前最大的可测量落差
（91,982px）。它不需要任何新功能，只需要调整渲染顺序与折叠。

**Independent Test**: 用 HTTP 取 `warm.one_liner` 的真实文本，再在 DOM 里定位它的
y 坐标——**契约驱动定位，不写死类名**（D-145a 教训）。

**Acceptance Scenarios**:

1. **Given** warm 模式下的排盘结果，**Then** 提交后用户**无需滚动**即可看到一句话
   结论——即它落在提交后的首屏视口内。
   ⚠ **口径订正（R129a，见下方 §Success Criteria 脚注）**：原文写「文档绝对
   y ≤812px」，实测不可达且不应由 spec 规定实现方式。改为**相对提交后视口**度量。
2. **Given** 同一屏，**Then** 能量卡（本命元素/幸运色/幸运数字）也在第 1 屏内可见，
   或紧随其后的一屏内。
3. **Given** 结果区，**Then** warm 模式总高度 **≤4 屏**。当前 124 屏。
4. **Given** 用户提了问，**Then** 对该提问的回应出现在结论之后、古籍之前。
5. **Given** 任意功能（排盘/六爻/塔罗/黄历/起名/桃花/合婚），**Then** 上述四条同样成立
   ——不是只修排盘一处。

---

### User Story 2 — 古籍是可展开的证据，不是默认的正文（Priority: P0）

**作为**普通用户，**我想要**古籍原文默认收起来，
**以便**页面短到能读完；**作为**想核对的用户，**我想要**展开后看到一字不差的原文。

**Why this priority**: 这是本 spec 唯一触及宪法第三条的地方，必须写清楚边界。
**折叠 ≠ 删除。** 项目的立身之本是「有出处」——R118a-03 那条 MAJOR 就是
「原文有了、出处没了」。所以本 story 的每条都成对出现：既要收起来，又要可核验。

**Independent Test**: 用 `textContent`（不受 `display` 影响）核对页面上是否仍
包含 API 返回的每一段原文与出处。

**Acceptance Scenarios**:

1. **Given** warm 模式结果区，**Then** 默认可见的单个文本块 **≤400 字**。
   当前最长 7,955 字。
2. **Given** warm 模式结果区，**Then** 古籍原文默认可见字数占结果区 **≤40%**。
   当前 56%（去重前 93%）。
3. **Given** 折叠状态，**Then** 页面 `textContent` 中**仍包含** API 返回的每一段
   原文与每一条出处——折叠只改可见性，不改内容。
4. **Given** 展开古籍，**Then** 原文与 API 返回**逐字节一致**（不得为了排版而改
   标点、换行、异体字）。
5. **Given** 任一引文，**Then** 出处（书名 + 页锚点 + 文件名）与原文同时可见，
   不允许只显示其一。
6. **Given** 同一段古籍，**Then** 在结果区**只渲染一次**——当前实测渲染两次
   （见 §1.1，R128a-01）。

### User Story 3 — 大白话优先可一键切回（Priority: P1）

**作为**产品所有者，**我想要**这套新版面能一键切回原来的版面，
**以便**即使我不认可这个信息层级，也不损失任何已完成的工作。

**Why this priority**: 与 003 US5、004 US3 同构，理由也同构——这是「优化轨自主
决定版面」得以成立的前提。**注意本条与既有的「温柔版/专业版」切换器是同一个开关
还是两个，由优化轨决定**，但必须满足下方判据。

**Acceptance Scenarios**:

1. **Given** 新版面已上线，**When** 切到专业模式，**Then** 输出**逐字节等于**
   `web/baselines/voice_baseline.json` 冻结的基线（`specs/004` 判据 9，
   `web/baseline_voice.py` 把关，当前 sha256 `b0461df2…`）。
   ⚠ **R190b 订正**：`b0461df2…` 是 R189b 之前的值。R189b 因 R131a-01 修复
   （提问进检索 → 3 个带提问用例的证据集合法变化）重冻基线，现值
   `97f0681e…`。判据 9 的**本义未变**（专业模式逐字节冻结、由同一脚本把关），
   变的是被冻结的输入证据。实测：`<py> web\baseline_voice.py` 退出码 0，
   `14 用例逐字节一致`。原值保留备查（D-008 先例）。
2. **Given** 任一模式，**Then** UI 冒烟全部用例通过、13 道闸门全绿。
3. **Given** 切换动作，**Then** 用户已有数据（历史、收藏、偏好）不受影响。
4. **Given** 用户的选择，**Then** 下次打开保持。

### User Story 4 — 轻量入口与可分享（Priority: P2）

**作为**小红书用户，**我想要**首页就有「今日」类的轻量入口，结果能一键存成图，
**以便**每天愿意点开、看到好的愿意发笔记。

**Why this priority**: 这承接 `specs/004` 的 M2/M3（今日运势聚合、分享海报），
两者**尚未开工**。放在 P2 是因为 US1/US2 不做完，做这些等于给一个看不懂的结果
加分享按钮。

**Acceptance Scenarios**:

1. **Given** 首页，**Then** 有「今日」类聚合入口（黄历宜忌 + 本命日运一句话 +
   幸运色/数字），点击可达。
2. **Given** 任一结果区，**When** 点分享，**Then** 生成竖版图且内容非空
   （数据量有下限阈值）。
3. **Given** 分享图，**Then** 含「仅供娱乐」标识，且**用浏览器原生绘图实现、
   零新增外部依赖**（`html2canvas` 已判 REJECTED，见 D-151a；实测原生 Canvas
   出图 900×1200 约 191KB 可行）。
4. **Given** 分享图生成，**Then** 图片不落任何数据库、运行时零外部网络请求。
5. **Given** 同一结果，**Then** 两次生成的图逐字节一致（确定性）。

### User Story 5 — 引文相关性（Priority: P3，需先调查）

**作为**用户，**我想要**展开的古籍确实与我的问题有关，
**以便**「有出处」不只是形式上的。

**Why this priority**: 实测排盘带出的 12 段引文里，有「遁甲演義」
（`王璋曰乙竒臨乾驚門庚辛囚死乃木入金鄉也`）、「太乙金鏡式經」
（`欽定四庫全書太乙金鏡式經卷六唐　王希明　撰`）这类与「八字感情运」关联很弱的
内容。**这可能不是版面问题，而是检索相关性问题**——那属计算层。

⚠ **本 story 优先级最低且需先调查**，不要在没有量化相关性之前改检索逻辑。
若调查确认相关性有问题，应作为独立缺陷条目提出，由优化轨决定修法。

**Acceptance Scenarios**:

1. **Given** 一次带提问的排盘，**Then** 能给出每段引文「为何被选中」的可读理由
   （当前响应里已有 `why` 字段，实测值如「月柱」——但未上屏）。
2. **Given** 引文列表，**Then** 与提问主题明显无关的段落不排在前列。
3. **Given** 相关性判据，**Then** 它是可自动测量的（如提问关键词与引文的命中关系），
   而不是人工感觉。

### 判据 1 的口径订正（R129a：我写错了度量基准）

原判据 1 写「一句话结论的**文档绝对 y** ≤812px」。优化轨 R184b 指出它不可达，
**我亲自复验，声明成立**：

    #result 自身绝对 y = 3,005px，构成（375px 视口逐块实测）：
      brand         y=   28  h= 55
      #dailyCard    y=  111  h=577
      #funcGrid     y=  712  h=618
      recent-section y= 1366  h=467
      recent-section y= 1860  h=133
      表单 card      y= 2013  h=888（表单本体）
    → 即使结果区第一个像素就是那句话，y 也是 3,005px = 阈值的 3.7 倍

**这个判据的错在于：它把「用户看不看得见」错写成了「文档里的绝对位置」。**
用户提交后关心的是「我现在这一屏能不能看到结论」，而不是它在文档流的第几像素。
把绝对 y 当判据，等于隐含要求前端必须删掉或藏起首页的品牌区、今日运势卡、
功能卡——**那是 spec 在规定实现方式，越界了**（同 D-145a：判据该管行为，不管做法）。

**故订正为**：度量「一句话结论相对**提交后视口顶部**的偏移」。
优化轨自选实现（它的方案是提交后把上方各块收起 + 44px 返回条，实测
3,005 → 136px，一句话落到 482px；也可以用滚动定位、或结果区独立视图——
**做法由它定，判据只看用户提交后是否无需滚动就能看到结论**）。

⚠ 但有一条边界：**上浮不得把「今日入口」永久藏死**（判据 11 要求它可达）。
返回后首页各块必须完整恢复。

## Assumptions

- 不改任何算命/读书的**计算结果**，不改 `data/` 语料。
- 不引入新的外部依赖、不联网抓新语料（宪法第二条红线第 3 项）。
  若某方向必须引入，按处置规则记 BLOCKED 换方案，不询问用户。
- 折叠/展开的具体交互形态（`<details>`、标签页、抽屉）由优化轨自主决定。
- 「首屏」以 375×812 为基准（`specs/003` 已守住的移动端基线）。

## Out of Scope

- 重新引入生成式模型解读（BYOK 的七条约束见 D-146a，待用户拍板，默认不做）。
- MBTI × 塔罗（已 REJECTED，D-147a：语料零命中，与「有出处」立身之本冲突）。
- 把星座/十二宫与古籍隔离（已推翻，D-148a：十二宫是《星學大成》的真实内容）。
- 删除或改写任何古籍原文与出处（宪法第三条）。
- 小程序/App 形态。
