实测 `interpretation.sections` 顺序与行数：

**「感情运怎么样？」的完整答案是一行**：
`夫妻星出现在：年支藏干甲(七杀)——夫妻星现于盘中，相关事项在四柱里有着落点`

六爻更极端，实测原文：
`系统只给卦象坐标与經文原文，不代为断事——请据下方卦爻辞原文对照所问（G7：无证据不推测）`

**我同意提案对 G7 的判断，且这是本 spec 成立的前提**：G7 的原始定义是
「能承认证据不足」，防的是**伪造引文**（`eval_g7.py` 实测 FABRICATIONS 0
就是在守这个）。它从不要求「不许用人话说明已经算出来的坐标」。
把 G7 用到拒绝回应用户提问的程度，是**把守则当成了挡箭牌**。

### 实测推翻提案的一处判断（十二宫不是「西方占星」）

提案 §4 P2 把星座定性为「西方占星为娱乐模块，非本项目古籍语料」，
要求与古籍**物理隔离、不混排、不进 corpus**。**这个定性经实测不成立。**

我在 `corpus.db` 全文检索了十二宫名，结果：

    白羊 49 条（KR3g0041×40）　金牛 52 条（×47）　巨蟹 39 条（×36）
    獅子 45 条（×35）　天秤 30 条（×28）　雙魚 50 条（×42）
    同一单元内最多同时出现 10 个宫名 → KR3g0041 @KR3g0041_WYG_015-29b

`KR3g0041` 实测书目信息：**《星學大成》，命理类，31 文件 472,894 字**，
kanripo 来源、sha256 与 fetched_at 齐备。真实原文（`@KR3g0041_WYG_001-1a`）：

> 定十二宫神二十八宿分野所屬　角亢**秤宫**辰屬鄭　氐房心卯**蝎**宋遊
> 尾箕**人馬**燕寅位　斗牛**磨蝎**丑吳流　女虚危**瓶**齊子地　室壁**雙魚**亥衛州
> 奎婁**白羊**魯國戌　胃昴畢酉趙**金牛**　觜參**隂陽**申晉地　井鬼**巨蟹**未秦州
> 柳星張周**獅子**午　翼軫**雙女**楚已

**结论：黄道十二宫是本项目语料里的中国传统星命学内容**（七政四餘 / 星學体系），
不是外来的娱乐拼贴。它与二十八宿分野同表并列，有页锚点、有出处、可引用。

这把 P2 从「要隔离的异物」变成了**本项目最有说服力的差异化**：
竞品的星座日运是拍脑袋文案，我们的可以挂《星學大成》的真实引文。
因此本 spec **不要求**星座与古籍物理隔离，**反而要求**它必须带引文——
详见 User Story 4。

### P3 MBTI 不收编的理由

同一次检索，MBTI 相关词（`MBTI`、`人格类型`、`十六型`）在语料里**零命中**。

MBTI 是 20 世纪的心理学量表，与「能否追溯到印本/底本」这条判据（宪法第三条）
没有任何接口。做它意味着在一个以「有出处」立身的产品里，加一个**纯粹无出处**
的模块——那正好抵消了 P2 刚刚建立的差异化。

这不是说 MBTI 不受欢迎，是说它与本项目的立身之本冲突。若用户明确要，
它应当是独立产品，不该挂在「知命」的古籍语料旁边。**记为 REJECTED**，
理由与实测依据同步写入 `docs/TASK_LEDGER.md`。

### P0/P1 是否越界（优化轨点名问的）

不越界。宪法第五条的边界是**文件所有权**（`src/guji/**`、`web/**` 归优化轨），
不是「内容层归谁」。文案与呈现都在优化轨的文件里，做法由它定。
审查轨管的是**判据**：下方 User Story 与 Success Criteria 就是我要验的东西。

## User Scenarios & Testing *(mandatory)*

### User Story 1 — 问了什么，先答什么（Priority: P1）

**作为**一个问「我的感情运怎么样」的用户，**我想要**打开就先看到一句回应我这个
问题的人话，**以便**不用先读完八行推导链才找到与自己有关的一行。

**Why this priority**: 这是「看不懂也不想看」的**主因**，且实测可证：用户的提问
排在第 5 节、只有 1 行，前面 15 行是坐标与推导。信息架构把校验者的需求
（可核验）放在了用户需求（我想知道答案）之前。

**Independent Test**: 取结果区**首屏可见范围**内的文字，统计其中术语数与
是否包含对提问的回应。

**Acceptance Scenarios**:

1. **Given** 带提问的排盘，**Then** 结果区**第一节**就是对该提问的回应，
   不是坐标或纳音。
2. **Given** 结果区首屏，**Then** 一句话结论非空且不超过 20 字。
3. **Given** 结果区首屏，**Then** 命理术语出现次数 ≤3（术语表写死在探针里，
   当前首屏全是术语）。
4. **Given** 推导依据（如「依据：戊己同为土，异阴阳」），**Then** 默认折叠，
   展开后**逐字不变**——校验能力不得因为好看而丢失。
5. **Given** 任意提问与生日，**Then** 同输入必得同输出（两次运行逐字节相等）。

---

### User Story 2 — 温柔说话，但不算命定生死（Priority: P1）

**作为**在情绪低谷时来问一句的用户，**我想要**语气是朋友而不是审计报告，
**以便**读完觉得被理解，而不是被判决。

**Why this priority**: 用户指示的原话是「普通人看不懂也不想看」。看不懂是结构问题
（US1），不想看是口吻问题。但温柔不能滑向「断吉凶」——那会同时踩两条线：
宪法第三条（生成文本不得冒充有据结论）与产品责任（不作现实决策依据）。
所以这条要求同时约束**下限**（要像人话）与**上限**（不许断命）。

**Independent Test**: 对固定输入的输出做禁用词与句式检查。

**Acceptance Scenarios**:

1. **Given** 任意输出，**Then** 不含吉凶断言与现实指令（「你会脱单」「一定发财」
   「该分手」等，禁用词表写死在探针里）。
2. **Given** 任意输出，**Then** 不含医疗、投资、法律建议。
3. **Given** 任意输出，**Then** 免责声明存在且明确标注「仅供娱乐」，
   但**不以它收尾压轴**（当前以「非现实决策依据」结束）。
4. **Given** 六爻等当前拒答的功能，**Then** 对用户提问给出**基于已算出坐标**的
   描述性回应，不再只回「不代为断事」；同时引文与出处逐字节不变。
5. **Given** 任一功能，**Then** 温柔文案与古籍引文在结果区可区分
   （承接 003 US6：三类内容视觉可辨）。

---

### User Story 3 — 口吻方向可一键切回（Priority: P1）

**作为**产品所有者，**我想要**新口吻能一键切回现在的输出，
**以便**即使不认可优化轨自主选定的文案风格，也不损失已完成的工作。

**Why this priority**: 与 003 US5 同构，理由也同构——**这是「优化轨自主决定文案
风格」得以成立的唯一前提**。文案比配色更主观，更需要这条。

**Acceptance Scenarios**:

1. **Given** 新口吻已上线，**When** 切到专业模式，**Then** 输出**逐字节等于**
   本 spec 创建时的现有输出（该基线由探针固定断言，不是靠记忆比对）。
2. **Given** 任一模式，**Then** 全部功能可用、引文出处非空、13 道闸门全绿。
3. **Given** 切换动作，**Then** 用户已有数据（历史、收藏、偏好）不受影响。
4. **Given** 两种模式，**Then** 用户的选择在下次打开时保持。
5. **Given** 两种模式，**Then** 各自都满足 003 的对比度与点击目标判据。

---

### User Story 4 — 幸运色/数字/星座必须有出处（Priority: P3）

**作为**会把结果截图发小红书的用户，**我想要**幸运色、幸运数字、星座日运，
**以便**有可分享、可自我认同的轻量内容。
**作为**产品所有者，**我想要**这些内容**都能指到古籍**，
**以便**它们是「有出处的玄学」而不是又一个随机数生成器。

**Why this priority**: 这是本项目相对竞品的**结构性优势**，且实测支撑充分：

- 河图数：`天一生水` 11 条命中、`天五生土` 3 条，可挂引文
- 五行配色：`五色` 74 条命中
- 十二宫：《星學大成》完整十二宫表 + 二十八宿分野，有页锚点

**Independent Test**: 每个幸运项与星座结论都能给出一条可核验的语料出处；
固定输入固定输出。

**Acceptance Scenarios**:

1. **Given** 任一幸运色/数字，**Then** 它由写死的映射规则推出（非随机），
   且能给出该规则对应的语料出处。
2. **Given** 同一用户同一天，**Then** 幸运项逐字节可复现；跨天变化有明确规则。
3. **Given** 十二宫日运，**Then** 12 宫 × 同一天全量输出逐字节可复现。
4. **Given** 十二宫内容，**Then** 带真实语料引文与出处
   （**本 spec 明确不要求与古籍隔离**——实测证明它就是古籍内容，
   见上方「实测推翻的一处判断」）。
5. **Given** 任一新增文案，**Then** 它不进语料库与知识库
   （只落已授权的历史库），且现有隔离探针覆盖到它。

---

### User Story 5 — 结果能一键变成可分享的图（Priority: P3）

**作为**小红书用户，**我想要**一键把结果存成竖版图，**以便**直接发笔记。

**Why this priority**: 用户画像里「可分享截图」是平台习惯。当前零可分享物。

**Acceptance Scenarios**:

1. **Given** 任一结果区，**When** 点分享，**Then** 生成竖版图片且内容非空
   （图片数据量有下限阈值，探针可测）。
2. **Given** 生成的图，**Then** 含「仅供娱乐」标识。
3. **Given** 首屏与分享流程，**Then** 运行时零外部网络请求、零 CDN
   （当前实测零外链资源，**不得退步**）。
4. **Given** 分享图生成，**Then** 图片不落任何数据库。
5. **Given** 分享图生成，**Then** 用浏览器原生绘图能力实现，**零新增外部依赖**。
6. **Given** 同一结果，**Then** 两次生成的图逐字节一致（确定性，与本 spec 全篇
   「同输入必同输出」一致）。
7. **Given** 页面响应式版式发生改动（003 视觉升级），**Then** 海报版式不受影响
   ——海报是固定 3:4 版式，不是网页快照。

### `html2canvas` = REJECTED（R126a 实测决定，详见 D-151a）

优化轨提案「唯一新依赖 `html2canvas`（MIT，~48KB 单文件），按宪法 §5 记
provenance」。**审查轨判 REJECTED，并已实测替代方案可行——修复轨可直接施工，
不必等任何人授权。**

理由不是"手续不全"，是**它不必需**。实测：浏览器原生 Canvas 2D 喂真实
`warm.energy_card` 数据一次绘制完成——

    真实字段：element 土 / lucky_numbers [2,7] / lucky_colors ['红','紫']
              basis 三条（含「幸运数字 = 河图数「火」（生土者）」）
    出图 900×1200（3:4 竖版），toDataURL 261,686 字符 ≈ **191KB**
    → 判据 12（>40KB）PASS

含标题、能量卡全字段、幸运色色块、**出处三条**、「仅供娱乐」水印，
上方 1–7 条 Acceptance 零依赖全部可满足。

三条实质理由（不止是省一个依赖）：

1. **截 DOM 是错的技术选择**。海报要固定 3:4 版式，页面是响应式的，两者本不必
   相同。截 DOM 意味着 003 每次改 CSS 都可能让海报变形——而海报是要发小红书的。
2. **确定性**。原生绘制同输入必得同输出（判据 6）；截 DOM 依赖当时的字体加载、
   滚动位置、动画帧，与本 spec 全篇纪律不合。
3. **依赖的成本不是体积，是它以后会不会变、要不要跟版本、出问题算谁的。**

宪法第二条红线第 3 项的处置规则是「这个任务的当前方案错了……换任务/换方案」。
本条即换方案，不是挂起。若用户明确说"就用 html2canvas"，那是授权、照办；
但**默认不做，且不为此停下等待**。

## Assumptions

- 温度来自**写死的确定性文案**，不重新引入生成式模型（P4 见下）。
- 幸运项与十二宫的映射规则写死、可引古籍，不用随机数。
- 「闺蜜口吻」的具体措辞由优化轨自主决定，候选与否决理由记入
  `docs/DECISIONS.md`；用户的否决权由判据第 9 条（一键切回）保障。

## Out of Scope

- **MBTI × 塔罗**：REJECTED，语料零落点（见上方理由）。
- **BYOK AI 解读**：不在本 spec 内。约束已预先落定 `docs/DECISIONS.md` D-146a，
  用户将来拍板时即有现成边界，不需临时讨论。
- 新语料入库、小程序/App 形态、生成链接分享服务。
- 修改计算层语义与 `data/` 语料。
