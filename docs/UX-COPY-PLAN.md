## 二、文案丰盈方案（核心工作）

### 现状诊断
以「最近感情怎么样」实测：warm.reply 7 行、平均每行 22 字，
行与行是**并列的事实碎片**（盘里少信息→不瞎编→相刑→同伴力→
劫财→时柱），没有因果串联，读着像清单不像解读。

### 文案骨架规范（每个功能结果段统一）
```
①接情绪（可选）：问题里带情绪词时先接住——「问感情的多半心里有事」
②给结论：一句话先落锤（≤25字，立场明确不含糊）
③讲来由：把 calc 里的 1-2 个真证据译成人话——「因为你盘里 X，所以 Y」
④给用法：今天/这周能做的 1-2 件具体小事（不是鸡汤，是动作）
⑤收口：一句不落井下石也不空头保证的话
```
**硬指标**：bazi/tarot/dream/hehun 的 warm.reply 目标 4-6 句、
总长 120-220 字；少证据时不硬凑，转「温柔的坦白」口径。
所有素材必须来自 calc/warm 既有字段——**零虚构事实**，只是
把已算出的碎片织成段落。

### 落点清单（按优先级）
1. `voice.py` bazi reply 组装器：把「十神行 + 地支关系行 + 流年行」
   从并列 append 改为因果串写（结论先行+「因为」连接）
2. `voice.py` one_liner：「盘里信息偏少」这种冷拒感重写为
   「感情这块盘上说得不多，但盘外的你有的是办法」
3. tarot `tarotDeepRead` 三段式扩写：连起来看→你该留意→现在可以
   做，每段补一句「为什么这么看」（用牌位关系）
4. dream `echo/act` 已较暖，主要做长度均衡（短的补一句「老话里」
   出处行，长的砍冗词）
5. qiming `one_liner`/收口行重写（同上述 qm-close 口径）
6. hehun/friction 文案复审：低分盘不许出现「不合适」式判死刑

### 禁词/别扭词清单（审计基线）
- 禁：不藏 / 念三遍 / 落点 / 硬凑（面向用户的「不瞎编不硬凑」
  可留「小满不乱猜」式人话）/ 派发 / 承载 / 两头凑 / 供你复验
- 替：事实不足时→「这部分盘上写得少，小满不脑补」
- 规：所有确定性字段给白话注，术语保留但永远不当头一句

## 三、视觉补全方案

### 1. 梦符图鉴补全（40 个缺口 → 全量）
现状 52 符只配 12 图，「鬼/可怕的东西」等 40 个回落月熊。
方案：分批跑 `scripts/gen_r3250_assets.py` 同款管线补齐
（每批 ~10 张，奶油熊 IP 同风格）。高频优先批次：
鬼压床/黑影、大哭、掉头发、没穿衣服、分手、吵架、血/受伤、
赶不上车、被困、已读不回、上班被骂、偶像、老家、手机丢了。
全覆盖后 `DREAM_ART` 仍有 dream-bear 兜底，永不裸奔。

### 2. 十神可视化升级（命盘已有，再加一层「人话」）
现有：四柱格十神 chip 是术语原文（比肩/劫财…）。
方案：chip 文案改双行「比肩·同伴」（复用 `_TEN_GOD_TAG`
映射，零新数据）；悬停 title 保留术语全称。
卡通化选项：给 10 个十神各生一枚 24px 迷你图标是可选增强，
但 chip+人话标签已解决可读性，**先做文案双行，图标后议**。

### 3. 地支关系盘（可选增强）
现有五色分组色块已可读。若要做「环形十二地支关系图」：
12 支环形排布+合冲刑害连线，工程量大且移动端密集难读——
**暂列二期**，先靠色块+图例顶。
