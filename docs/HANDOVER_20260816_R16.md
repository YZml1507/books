## 7. 历史教训（新窗口必须吸取，否则受罚）

1. **正则工具结论会误判**：上一窗口用正则核 knowledge SQL 注入，正则误判 4 个"非参数化"，
   实际全参数化。教训：正则只作初筛，必须亲自看代码逐行核实。
2. **子 agent 声称的 P0 多为假阳性**：R5/R11/R12/R15 共核实子 agent 标的 P0，
   假阳性率约 70%。教训：子 agent 结论一律当"待复验"，亲自跑命令核实。
3. **台账/文档结论会过时或错误**：R8 第一轮修复破坏 T9（106/600 失败），台账先记"失败已撤销"，
   第三轮才成功。教训：台账记录修复"过程"而非只记结论，每轮都亲自跑闸门核实。
4. **docstring 与代码会矛盾**：R9 douay docstring 声称"续行累加"但代码丢弃续行；
   R14 renderMD docstring 声称"先 esc() 再结构化"但实际未调 esc()。
   教训：docstring 不可信，以代码为准，发现矛盾就修代码对齐 docstring（或反之）。
5. **边界输入测试必须亲自跑**：上一窗口多次通过 `python -c "..."` 实测边界输入，
   才确认假阳性/真红线。教训：不可只看代码推断，必须实跑复现。
6. **commit/push 必须闭环**：上一窗口曾因中断留下未 commit 的台账修改（R16），
   续作时才发现。教训：每轮修复完成后立即 commit + push，不留未闭环状态。
