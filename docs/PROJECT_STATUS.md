## 1. 项目是什么

「小满的解忧铺」——一个民俗向 PWA（渐进式网页应用）：

- **黄历**：每日宜忌/冲煞/吉时/建除十二神/二十八宿/彭祖百忌，含「找日子」
  （宜日榜）与「今天宜/忌 X 吗」判定门。
- **塔罗**：捣蛋签/桃花签/多牌阵抽牌，含星座速配、月相。
- **八字**：排盘（四柱/十神/大运/五行强弱）、合婚、起名、桃花。
- **聊天**：「小满」人格陪聊——确定性门层（正则/键表路由出真值事实行）
  + LLM 口吻层（事实进 prompt，模型只负责说人话）。
- **古籍研究底座**：47 部书/6 万+单元索引（FTS5+向量）、G1–G9 判据、
  研究线程——原项目母体，铺子在其上长出来。

技术栈：FastAPI + SQLite + 原生 JS PWA（Service Worker 离线壳）+
Sentence Transformers；部署在 Render（Docker），线上：
<https://books-ctsw.onrender.com/>（有访问口令门 `BOOKS_ACCESS_TOKEN`，
防陌生人白刷 LLM 调用量）。

### 打磨历程（循环优化 ~500 轮）

- **民俗白话面收口**：白话表从 0 铺到 ~1,600 词，近几批新增已近枯竭——
  以审计修坑为主而非铺词。
- **真值门几十个**：宜忌判定/找日榜/时辰榜/属相岁数互查/大事年表/星座反查/
  农历日名反查/神煞真值——能算的出真值，不能算的诚实说没这门。
- **误伤面收口**：撞键族（物名/品种/专名煞/玩笑话/歇后语）根治机制落地，
  每批误伤从几十处降到个位数。
- **方法定型**：问句电池双路管线（`chat_daily_facts` +
  `chat_huangli_facts` 并跑、全列打印）——单路测出的是假 EMPTY，
  首行打印测出的是假误伤。
- **近期四个结构修复**（用户直报 + 端到端实测驱动）：
  - PR #26：401 门匙浮层——SW 缓存壳下也能输口令进门；
  - PR #28：旧壳死循环三层自愈——SW 升级对门页放行、毒壳位自清理、

  - PR #30：双路电池定型 + 冲煞/日档/星座/桃花/财神诞补缺 +

## 4. 后续发展方向（三条路，取其一或组合）

### A. 当作品收尾（建议默认值）

边际收益已很小：新增白话词近枯竭、误伤率个位数。进入维护模式——
依赖/安全更新 + 用户直报修复即可，不再按批轮转。

### B. 继续打磨现有功能（不加新功能）

还可做的审计面：LLM 口吻/人格系统深审（拒答方式/敏感话题安抚/人设一致性）、
上述遗留观察项、残余撞键长尾。预计再 1–3 批后自然收干。

### C. 当产品运营（新一轮活，非打磨延伸）

缺口都在运营面：访问/留存埋点（现在没人知道多少人来过）、拉新入口与
裂变物料复用审计、LLM 调用成本控制、多用户数据模型（现在是单机档案）。
投入量级以「会话」计而非「打磨轮」。
