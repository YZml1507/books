## 2. 优化项（按优先级）

### O1 · P0 · PROJECT_STATUS.md 刷新（文档对齐，零风险）

现状矛盾（亲自核实）：该文档声称"Douay-Rheims 不支持"（R9 已实现 douay.py）、
"unit 表没有 suspect 列"（X-11 已加且 R17 修正归责）、"tier 2/3 七部书未建索引"
（R8 已实现 play/euclid/booksec）。读者若信它会得出错误现状。
**做法**：仿 BOOK_AI_ARCHITECTURE.md 的"阅读须知"置顶声明取代关系 + 重写当前
实测快照（13 闸门、44 部、G1-G9 全 PASS、双窗口并行现状）。

### O2 · P0 · MASTER_PLAN §6 过时修正（文档对齐，零风险）

§6 标题与正文声称"三类知识物理隔离（G8，未实现）/目前只有 Source 空真"，但
knowledge.py + knowledge_schema.sql + knowledge.db 已实现且 assess_goals G8=PASS。
**做法**：§6 改为指向 knowledge.py 的实现现状，保留原设计 rationale。

### O3 · P1 · Deep Research API（愿景 §6/§7/§16/§17.1）

**新增 `src/guji/research.py`** + `web /api/research`：迭代式"检索即推理"：
1. R1 FTS 检索问题（fold 異體字扩展）；
2. 从命中提取地址（scheme=zhouyi 的卦/爻）→ at_address 聚齐该地址全部见证/层；
   多作品同地址 → compare_address 差异摘要；
3. 焦氏易林命中 → link 表跳转关联卦（G4 已建的多跳边，首次暴露为 API）；
4. 每步记录 (action, query, kept) → `steps[]` 返回，**链路可展示**（G4 判据原文）；
5. 证据集去重排序；零证据 → refusal（沿用 answer.py G7 纪律）。
**风险**：低——纯新增只读路径，不碰现有闸门语义；确定性算法无 LLM 依赖。

### O4 · P1 · 跨书概念研究 API（愿景 §7 Cross-book/§17.1"变"/§17.3"无为"）

**新增 `web /api/concept?q=`**：一个概念词跨全部 44 部的普查——每部命中数、
分层数（經/注/疏）、top 引文（带完整 citation）、zhouyi 同地址多作品对照。
这是跨书比较（§17.3）的地基：语料加入道德经/庄子（O7）后同一端点直接生效。
**风险**：低——search 的聚合视图，只读。

### O5 · P1 · LLM 研究解读端点（愿景 §17 最终体验）

**新增 `src/guji/llm_reader.interpret_research()` + `web POST /api/ask`**：
O3/O4 的证据集 → LLM 大白话综合（复用 llm_reader 纪律：两段式输出——服务器端
渲染的原文证据 vs 标注模型名的 LLM 解读；system prompt 强制只依据引文、资料未涉
及就明说；无 key 或检索拒绝时降级为纯证据返回）。
**风险**：中——生成文本红线按 GOAL §5 仅限用户授权层；引文一律由服务器从
Evidence 对象渲染，绝不采信 LLM 生成的引用（防伪页码，G2 纪律）。

### O6 · P2 · MCP Server（愿景 §11，下轮）

把 search/at_address/compare/threads/concept/research 暴露为 MCP tools，
让 Claude 等外部 Agent 直接研究本语料。需 `mcp` 包（经 7897 装）或手写 stdio
JSON-RPC。**本轮只设计不实施**（依赖安装+协议符合性验证工作量大，独立成轮）。

### O7 · P2 · 语料扩展：道德经/庄子（愿景 §17.3，下轮）

跨书思想比较（"无为"）需要多家语料。需新 scheme 解析器 + 来源合规核查
（Kanripo KR1a0001 系已有道德经？核实后走现有 manifest 管线）。数据工作独立成轮。

### O8 · P2 · 评估扩展：跨书/版本意识/研究深度（移交审查轨协商）

eval 脚本在 scripts/（审查轨领土）。本轨在 src/guji 内为 O3/O4 附带自测
（`__main__` 自验），正式 gate 化需要时与审查轨协调接线。
