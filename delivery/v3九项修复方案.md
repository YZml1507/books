# v3 修复方案：九项体验缺陷（定位 → 根因 → 修法 → 验证）

依据：2026-08-28 晚你体验反馈的九个问题，全部已逐条复现/代码定位。**方案先行，本文档即改动清单**；涉及改码的每条都标了影响面与验证方法。

## P1 「查看完整解读」页面空白（最严重）
**定位**：`app.js loadDailyDetail()`（#dailyMore 按钮）。Playwright 实测：内容其实渲染了（12756 字符、`#dailyDetail` visible、clientHeight=934px）——**不是没渲染，是"看不见"**。
**根因**（两个叠加）：
1. `.fx-watch .fx-in` 入场动画类（IntersectionObserver 触发 opacity 0→1）挂在注入的 `.card` 上；首页底部该区域若无 IntersectionObserver 触发或动画被 previous 状态卡住，内容 opacity:0 → 用户看是空白。
2. 展开后没有把详情滚动进视口，且 `.daily-detail` 容器可能被父级 `overflow/height` 裁切，用户视角=点了没反应。
**修法**：注入后立即 `target.scrollIntoView({behavior:'smooth', block:'nearest'})`；给 `#dailyDetail .card` 强制 `opacity:1`（覆盖动画类，或注入完成后主动 addClass 触发）；`.daily-detail` 容器放开 max-height 裁切。
**验证**：Playwright 点开后断言 `getBoundingClientRect` 在视口内 + 截图非空白 + 抽样塔罗/命盘/每日三类入口。

## P2 首页图标正常，进功能页又变"原始图标"
**定位**：`renderDecoration()` 只给 bazi/qiming/taohua 三视图生成装饰 banner，且 `.deco-icon` 里是 `??` 乱码 emoji（源码即乱码）；tarot 实测 `NO-DECO`。
**根因**：结果卡顶部的"装饰图"是一套独立的 CSS 渐变+emoji 体系，从未接入 v2 奶油资产；emoji 在用户设备显示为原始乱码字符。
**修法**：`renderDecoration` 重写为统一走 `/static/cream/cream-icon-*.jpg` 图标 + 奶油渐变底（与首页卡片同语言）；补齐 tarot/hehun/huangli/xingzuo/liuyao 全视图 preset；乱码 emoji 全部清除。
**验证**：逐视图截图检查装饰区与首页观感一致、无乱码。

## P3 取名：风格切换无效 + 全是两字名
**定位**：后端 `classical_names.py` 的 full_names 全部 single（实测 24/24 单字）；风格切换在前端 `_styleShift` 错位切片，但池子=8 时三档共用同一批（代码注释自认）。
**根因**：
1. 双字名生成逻辑存在（`_full_name_combos`），但 `classical_names.generate_classical_names` 主路径只产单字典故名——v1 起就没把双字池接进来。
2. 风格切换仅在 `池>12` 时错位；现在 top_n=8 池=8 → 永远同一批。
**修法**：后端把典故双字名并入 full_names（复用 `_full_name_combos` 的双字组合，配典故寓意文案，三字名=姓+双字，占比 ≥1/3）；风格切换改为**后端过滤口径**（给 generate_classical_names 加 style 参数：classics=诗经/书经源，chuci=楚辞源，fresh=柔美字池，all=全部——数据里 origin 字段已带书名可过滤），前端把 style 传给 API。
**影响面**：schemas.QimingRequest 加可选 style 字段（additive）；selftest qiming 断言不查风格，安全。
**验证**：四风格各取 8 名，集合差异显著；单/双字名混合（双字 ≥1/3）；Playwright 实点四档按钮断言列表变化。

## P4 内部编码外露（@KR1a0001_tls_043-2a (KR1a0001_043.txt) · 經）
**定位**：`renderHits`/`renderCiteTree` 直接渲染 `h.citation` 原文；citation 由后端拼 `书名 @地址 (文件名) · 层`。selftest:190 明确断言 citation 必含 @ 和 file——**后端契约不能动，前端渲染层清洗**。
**修法**：前端加 `humanCite(citation)` 清洗函数：剥离 `@...(...)` 段与文件名，只留「书名 · 篇名/层位」人话（如「周易 · 師卦 正文」）；renderHits/renderCiteTree 全部走它。
**验证**：全站 DOM 检索 `@KR`/`.txt` 零命中；截图引文区。

## P5 AI 回复裸露 markdown（**加粗** 原样显示）
**定位**：聊天/AI 润色渲染统一走 `esc()` 纯文本。
**修法**：新增 `renderRichText()`：先 esc 防注入，再把 `**x**`→`<strong>`、`*x*`→`<em>`、换行→`<br>`、`- ` 列表→`<ul>`（白名单式，不引入完整 md 库）；聊天气泡、ai-polish、点评块全部换用它。
**验证**：发一条带 ** 的消息，气泡里显示为加粗且无 `**` 字符。

## P6 引擎说明外露（guji.interpreter/1.0（确定性规则，无 LLM））
**定位**：`interpreter.py` 5 处 `engine` 字段 + 前端 1767 行 `interp-badge` 直接展示。pro_render_baseline.json 的 h3 指纹里含该串（判据 9 钉死）。
**修法**：改前端 1767 行：badge 不再显示 engine 字段，改固定文案「小满解读」；同时把 pro_render_baseline.json 对应指纹更新（基线是"渲染结构指纹"，本轮已获准视觉大改，基线随新事实更新并注明）。后端 engine 字段保留（接口契约），只是不再显示。
**验证**：全站检索 `guji.interpreter` 零命中；selftest 闸门环境重跑（基线更新后）。

## P8 返回/查询后跳回顶部
**定位**：实测实锤：滚到 2987px → 进命盘 → 返回 → `scrollY=0`（提交后返回也是 0）。`showView` 里虽有 `_sy` 恢复逻辑，但 R205b 注释里的恢复只记不还（`_sy` 恢复代码在函数尾部缺失/被后续改动移除——实测为准）。
**修法**：`showView` 尾部恢复 `_sy`（切回 home 时 `window.scrollTo(0,_sy)`）；`.func-card` 点击 handler 里记录各视图进入前的首页滚动位（每视图独立记忆更稳）；视图内查询（摇卦/黄历/起名等）结果渲染后不调用任何 scrollTo 顶部的逻辑，`revealResult` 保持只滚到结果区。
**验证**：复现脚本重跑：y_before≈y_after_back；提交排盘后返回 scrollY 不为 0。
